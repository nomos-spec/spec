# Resolution vectors (NOMOS-SPEC-014, Active; 0.4.0 additions Draft)

The conformance vectors for [NOMOS-SPEC-014](../spec/NOMOS-SPEC-014.md): which authorities
govern an act in a context at a time, with evidence that the enumeration is complete relative
to the relying party's pinned registrars.

`vectors.json` holds 33 vectors. Each is a **world** (registrar records and pins), a **query**
(`context` + `at`), and the expected result:

- `expect` — what a conforming resolver answers;
- vectors with an `ablate` field also carry `expect_ablated` — what an implementation missing
  exactly that condition answers, i.e. the attack succeeding.

The ten attack vectors are NOMOS-SPEC-014 §8's necessity constructions, each built from
genuine artifacts alone. The C7 ablation judges membership at the vector's `ablate_at`, a stale
instant, while closures are still judged at the query time:

| Vector | Condition it proves necessary |
| --- | --- |
| `attack-applicability-hiding` | C5 — the set comes from pinned logs, never the carrier |
| `attack-jurisdiction-squatting` | C6 — a claim binds only within the certified scope (prevents wrongful refusal; an added authority never causes a wrongful commit) |
| `attack-zombie-authority` | C7 — membership is judged at `t`, not at a stale instant |
| `attack-starved-resolver` | C8 — an unreachable pinned registrar yields INCOMPLETE |
| `attack-stale-closure` | C8 — a stale closure yields INCOMPLETE |
| `attack-withdrawal-under-closure` | C8 — a closure must agree with the registrar's own log |
| `attack-stale-view` | C8 — a copy of a log older than the relying party's bound yields INCOMPLETE |
| `attack-misdescribed-act` | CF — a witness-required context field without its attestation is UNDECIDED, never FALSE: an unverified value cannot remove law |
| `attack-delegated-squatting` | C6 through delegation (0.4.0) — a delegate's certificate is the edge AND its recognizer's |
| `attack-self-asserted-scope` | 0.4.0 — nothing a registrar states about itself enters its certificate |

0.4.0 adds deferral (`deferral-*`: a recognition edge dissolves a conflict and removes no law;
only a registrar's own log can waive its precedence; an undecided edge holds the resolution
open), recognition windows (`recognition-ended`, `recognition-not-yet`) and delegation
(`delegation-resolved`, `delegation-unknown`).

A conforming resolver MUST produce every `expect`, MUST NOT produce any `expect_ablated`
outside an explicit test-only ablation mode, and MUST answer byte-identically under any
shuffling of registrars, claims, recognition edges and pins.

Queries MAY carry `witnessed` (field → attested witness classes); claims MAY carry
`witness_required` (field → class). The CF ablation reads witness-required fields as if bare
values counted.

## Registrar logs (0.4.0)

`registrar-logs.json` holds 34 cases, generated by `generate_registrar_logs.py` (keys from
published seeds, RFC 6979 ES256, byte-identical on every run; every expectation written by hand):

- **log** (19): verify one copy of a log under a pinned key: Ed25519 and ES256 heads, a head for
  another log, a head replayed across logs, algorithm confusion, the wrong key, a high-S signature,
  key rotation (followed, pinned to the new key, a stale head under the old key, a forged rotation),
  rewritten and extended history, a stale head, a broken chain.
- **network** (8): assemble the world from pins and the delegations their logs name, then resolve:
  delegation, a delegate under a substituted key, an unreachable delegate, two recognizers naming
  different keys, a rotated delegate, the hop bound, a withdrawn recognition.
- **discovery** (7): `_nomos-registrar` TXT records: found, mixed with other records, a substituted
  key, another registrar, plain http, incomplete, another version.

```bash
python3 resolution-vectors/check_registrar_logs.py resolution-vectors/registrar-logs.json         # Python reference
python3 resolution-vectors/generate_registrar_logs.py | cmp - resolution-vectors/registrar-logs.json   # byte-identical
```

The Python reference (`python/nomosprotocol/registrar.py`) checks `log` and `discovery` cases whole
and `network` cases up to the world they assemble; `@nomosprotocol/verify` checks all of it,
resolution included.

## Running

The reference implementation (`@nomosprotocol/verify` 1.6.0) runs all 33 vectors, the
necessity table (each attack succeeds under exactly its own ablation and under no other), and
the shuffle check in CI. The resolver is also mechanized step by step in Lean 4:
[`papers/resolution/lean/`](../papers/resolution/lean/). **An independent implementation that passes this file is the condition
for NOMOS-SPEC-014 leaving Draft** — see [IMPLEMENTING.md](../IMPLEMENTING.md). We invite one.

## Derived mutant corpus (`mutants.json`)

`mutants.json` thickens the bar the way SPEC-008's mutants do: **773 mechanical mutations** of
the 33 vector worlds (22 operators — dropped and altered context facts, shifted query times,
removed, aged, re-signed and narrowed closures, ended, future-dated, superseded and revoked
claims, starved pins, narrowed and widened certificates, witness grants and wrong classes, and
second-order stacks of two operators), each with the expected outcome computed by the reference
resolver (`@nomosprotocol/verify`). Self-contained: world, query and `expect` per mutant, in the
same shape as `vectors.json`; `generated_from.sha256` pins the vector file it was derived from.

Status: **derived, not normative.** The hand-written `vectors.json` is the conformance suite a
person reviewed case by case; the corpus tests *agreement in bulk*. A divergence is a
reportable finding either way — in the implementation under test, or in the reference — and is
credited errata. Notably, the 40 `reclose-narrower` mutants distinguish the specification's
closure-replacement rule from closure accumulation, which no hand-written vector yet tests
([#44](https://github.com/nomos-spec/spec/issues/44)).

Generator: `scripts/gen-resolution-mutants.ts` in the platform repository, seeded and
deterministic (two runs byte-identical, self-checked before output).
